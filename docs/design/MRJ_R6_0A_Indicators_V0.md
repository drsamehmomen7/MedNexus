# R6.0A — Governed INDICATORS V0

**Status: CLOSED; human functional acceptance PASS.** Stage 07 completes the seven-stage Journey V0 functionally. Final visual design and Unified Journey UX acceptance remain deferred. Fresh end-to-end validation on the independent 20-report synthetic Ultrasound set is pending as **MRJ FULL-CYCLE VALIDATION V1**. There is no R7 stage.

## Purpose and authority

EXTRACT defines clinical facts; STANDARDIZE enriches representation; ANALYZE computes descriptive report-level metrics; VISUALIZE presents them; INDICATORS wraps selected AnalysisRun metrics in explicit, versioned measurable definitions. The persisted `mrj-radiology-analysis-v0.4` AnalysisRun is the sole numerical authority. Stage 07 never reads chart values, source report text, raw RadGraph entities, or canonical fact records to derive counts. It does not recount reports, recalculate eligibility, divide numerators by denominators, normalize measurements, or reinterpret assertions. This boundary leaves the indicator contract reusable by a future domain pack without integrating Public Health now.

The `POST /api/v1/understanding/analysis-runs/{analysis_run_id}/indicators` endpoint creates or returns a deterministic `mrj-indicator-run-v0.1` IndicatorRun. `GET /api/v1/understanding/indicator-runs/{indicator_run_id}` retrieves it. Runs and immutable definition snapshots are stored under the external `Analysis_Workspace/indicator_runs` and `Analysis_Workspace/indicator_definitions` directories, outside Git. The source AnalysisRun is read from the established collection store; a VisualizationRun is never a numerical input. An unavailable source returns `SOURCE_ANALYSIS_NOT_AVAILABLE`.

## Definition, result, and version

`IndicatorDefinition` (`mrj-indicator-definition-v0.1`) carries deterministic identity, version and revision, name, domain, type, analysis scope, source metric type, target concept/anatomy/laterality/assertion or field, explicit numerator and denominator definitions, inherited eligibility and exclusion rules, snapshot time window, inherited stratification/filter context, unit, interpretation scope, and status. Clinical frequencies and report-data coverage use `REPORT_LEVEL`; terminology coverage uses `FACT_LEVEL` because its denominator counts canonical facts. The first saved prototype used definition version 1; the corrected fact-level scope uses version 2, preserving the earlier immutable snapshot. V0 uses `ANALYSIS_COLLECTION_SNAPSHOT`; it never treats upload time as clinical time. `PATIENT_LEVEL` has no validated pseudonymous identity and `POPULATION_LEVEL` is unsupported.

`IndicatorResult` (`mrj-indicator-result-v0.1`) records its definition ID/version/revision, source AnalysisRun ID, collection ID/version, source-derived generated time, source metric path, copied numerator, denominator, supplied value, unit, inclusion/review/exclusion counts, coverage context, readiness, warnings, and provenance. Provenance preserves analysis policy, eligibility rule, included/excluded/filtered report IDs, source metric report lineage, target concept identity, and time-window rule. Historical run JSON embeds both immutable definitions and results. A changed governed definition cannot reuse the same ID/version: the catalog checks revision conflicts; future changed meaning requires a higher version. The same source run and V0 configuration yield the same IDs, ordering, and payload.

## V0 candidate policy and scientific interpretation

The system creates at most five leading PRESENT finding indicators, three diagnostic consideration indicators, three documented-negative indicators, three key data-coverage indicators (modality, body region, report/service date), three whole-fact standardization-coverage indicators, and up to three governed comparable measurement summaries. When ANALYZE supplies no comparable distribution, one measurement readiness entry has no value and is `NOT_READY`. This bounded catalog is a functional proof, not a row-for-row copy of the full metric inventory. User-authored definition editing is deferred; V0 has only deterministic system-generated definitions because authoring would require a larger governance workflow.

Clinical frequency results retain ANALYZE's report numerator, included-report denominator, assertion, concept identity, and value. `FAVORED` diagnostic considerations remain hypotheses; `ABSENT` facts become frequencies of documented absence, never positive disease findings. `UNMAPPED` facts can still have distinct MRJ concept identities; component terminology mappings do not become whole-fact matches. The interpretation is limited to included reports in the selected collection/version. There are no population estimates, patient-level rates, causal claims, performance targets, thresholds, or benchmarking judgments.

Coverage indicators copy ANALYZE CoverageMetrics. Thus zero available report dates among eight included reports is a valid **0 / 8 availability** result, while a future clinical indicator requiring a service-date window would be `NOT_READY` with `MISSING_REQUIRED_DIMENSION`. Whole-fact `MATCHED`, `NEEDS_REVIEW`, and `UNMAPPED` counts copy ANALYZE standardization coverage with its canonical-fact denominator. ANALYZE does not publish a percentage for these fact counts; V0 shows the exact ratio and leaves `value` null with `RATIO_NOT_PUBLISHED_BY_ANALYZE`. Component mappings are separate and terminology coverage is not clinical validity. Measurement summaries appear only from ANALYZE-approved comparable distributions and retain its type, dimension, unit, count, minimum, maximum, mean, median, and report-level numerator/denominator; INDICATORS performs no unit conversion.

## Readiness and validation safety

`READY` means a supported definition and source metric are computable under an eligible-only policy with a positive denominator. `VALIDATION_ONLY` means a numeric result exists but review-required reports were explicitly included for validation. `NEEDS_REVIEW` means the definition requires governance review. `NOT_READY` means no eligible denominator, no comparable measurement source, or a required clinical time dimension is unavailable. `INVALID` means the definition or source metric contract is inconsistent. A zero denominator produces `NOT_READY` and a null value, never a fabricated 0%, NaN, or infinity. A valid 0 / 8 **coverage** metric remains a true zero-availability result.

The existing `R4.0A Synthetic Radiology Validation Collection`, version 1, produces 18 V0 entries from AnalysisRun `342293c21b047b273c94954ee133912a`: 17 `VALIDATION_ONLY`, one measurement `NOT_READY`, and none `READY`. Eight review-required reports were explicitly included; this **does not imply human clinical review**. Among the copied results are cerebral atrophy 1 / 8, favored metastatic tumor consideration 1 / 8, documented absence of aspiration 1 / 8, modality coverage 6 / 8, body-region coverage 5 / 8, and report/service-date coverage 0 / 8. These examples are read from the saved AnalysisRun, never hard-coded into generation or UI.

## Journey UI and limitations

The existing Stage 06 workspace leads to **Stage 07 · INDICATORS** for the same AnalysisRun. The minimal workspace shows collection/version, source AnalysisRun, inherited policy, a prominent `VALIDATION ONLY` qualification when applicable, readiness counts, and separate definition/result groups for clinical findings, diagnostic considerations, documented negatives, data coverage, standardization coverage, and measurements. Each row shows the definition's numerator, denominator, eligibility, exclusions, time window, analysis level, result and readiness. Technical provenance is collapsed. The Journey stage attaches only when the document's Stage 05 AnalysisRun matches; upstream EXTRACT, STANDARDIZE, ANALYZE, or VISUALIZE reruns invalidate Stage 07. This is functional UI, not the final chart or platform design.

The Stage 06 → 07 handoff takes the authoritative `analysis_run_id`, collection ID, and collection version from the current VisualizationRun and checks any in-memory AnalysisRun for a match. The indicator endpoint loads the saved AnalysisRun; it never uses VisualizationRun chart rows as numerical input. A stale Uvicorn process started before the route was added returned generic HTTP 404 `Not Found` despite a valid source AnalysisRun. After restarting the current backend, human browser review confirmed ANALYZE → VISUALIZE → INDICATORS, all 18 indicators, the readiness summary, validation-only wording, provenance, and return/re-entry context. The UI distinguishes an unavailable route from a genuinely unavailable source run or expired in-memory Journey context. Browser refresh starts a new Journey in V0; the in-memory Journey is not persisted across server restarts.

No patient- or population-level indicator, user-authored indicator studio, target/threshold system, reliable service-date window, cross-domain Public Health implementation, or clinical validation program exists in V0. **Deferred provenance debt:** AnalysisRun metrics expose contributing report IDs but not contributing canonical fact IDs directly. The source collection snapshot retains governed facts, so fact-level audit currently follows report lineage back to that snapshot. A future audit chain should link Indicator → Analysis Metric → Canonical Fact IDs → Evidence Anchors; it is outside R6.0A closure. The separate 20-report synthetic Ultrasound set is reserved for fresh full-cycle Upload → UNDERSTAND → PROTECT → EXTRACT → STANDARDIZE → ANALYZE → VISUALIZE → INDICATORS validation. Stage 07 was not tuned to that set. Feature expansion pauses for the complete Unified Journey UX review after that validation, including navigation, collection transition, chart design, responsive behavior, visible technical IDs, and common Public Health/Radiology identity.
