# R3.0A — Radiology STANDARDIZE V0

**Status: ACCEPTED / CLOSED — human browser review PASS (5 October 2026).** The component-aware provider correction and Stage 04 Journey wiring are accepted. R2.0C remains closed. This is the minimum offline Stage 04 handoff; it does not implement ANALYZE, FHIR, a terminology administration UI, or the final Unified Journey design.

## Purpose and authority

UNDERSTAND owns structured study context, PROTECT owns safe patient context, EXTRACT owns clinical facts and meaning, and STANDARDIZE owns only terminology, unit, and study-identity representation. STANDARDIZE consumes a completed Radiology EXTRACT result's `clinical_synthesis.canonical_facts` plus structured UNDERSTAND context. It never parses report text or evidence to discover facts. It neither alters nor copies a full canonical fact; `source_fact_id` references the original fact, which retains its wording, assertion, hypothesis status, salience, observations, relationships, review reasons, and evidence anchors. The original EXTRACT result remains available in the same bounded JourneyRun.

## Output contract

`STANDARDIZE` stage result has `profile`, `report_id`, `source_extract_state`, `state`, `standardized_facts`, `standardized_study_context`, `summary`, and `technical_diagnostics`. There is exactly one `StandardizedClinicalFact` per source canonical fact. Each holds `source_fact_id`, `concept_mappings`, `anatomy_mappings`, `standardized_measurements`, `standardization_status`, review flags/reasons, and profile/source/provider-version provenance. No entire clinical fact is duplicated. Each `TerminologyMapping` records system, version if active, source text and fact ID, code/label if genuinely matched, status, match type, method, confidence when exact, review flag/reason, and candidate mappings when ambiguous.

Statuses are `MATCHED`, `NEEDS_REVIEW`, and `UNMAPPED`; match types include `EXACT_LABEL`, `EXACT_SYNONYM`, `BROADER`, `NARROWER`, `RELATED`, `AMBIGUOUS`, `MANUAL`, and `NONE`. Exact whole-label preferred terms take priority over exact whole-label synonyms, then structured canonical components are considered. Only one unambiguous exact preferred-label or synonym candidate from an active source-backed equivalent mapping may be automatically `MATCHED` for the looked-up term. Competing or non-equivalent candidates require review. No candidate yields `UNMAPPED` with no fabricated code. Provider unavailability or absent local reference data is diagnostic, not a technical failure. Terminology versions are drawn from active local reference configuration and never inferred from a filename or manifest alone.

## Component-aware correction (accepted)

The complete `display_label` is still the first lookup. If it is absent from RadLex, V0 reads only the accepted `canonical_concept` identifier. A named identifier supplies its full ordered concept name and, if compound, its terminal component; an open identifier supplies its existing unordered concept tokens. These are lexical components of an accepted fact, not newly inferred clinical heads. The provider never scans evidence or raw report text and never strips arbitrary words from a display label until a code appears. It does not add a clinical concept whitelist. RadLex clinical finding and imaging observation families can support concept components; domain signals such as severity are not clinical concept codes. Anatomy remains mapped solely from the separate accepted `anatomy` field.

`component_mappings` records exact source-backed codes for recognized components. Except when the whole underlying canonical concept exactly matches the display after its explicit `No` assertion prefix, a component code has `relationship_to_fact=BROADER`; the whole `concept_mappings` entry has no authoritative code, `match_type=BROADER`, and `mapping_status=NEEDS_REVIEW`. The complete fact's qualifiers, assertion, hypothesis, salience, evidence, and display remain in the original EXTRACT result. The standardized projection also carries `source_assertion_state` so an exact concept mapping for `No diverticulum` is visibly negative, never a positive diagnosis. Open identifiers do not establish which lexical token is the clinical head; their component hits are reviewable only. A related expression such as Hill-Sachs lesion versus Hill-Sachs deformity is not treated as equivalent or assigned the deformity code automatically. Ambiguous or related whole-label candidates remain review-required and take priority over component proposals.

Coverage is reported separately as whole-label exact mappings, exact component mappings, facts with partial/component standardization, facts needing review, and facts fully unmapped. Component counts are not a whole-fact mapping rate. `MRI` may be looked up under Playbook's exact `MR` spelling only when the underlying structured modality is MRI; this alias never creates shoulder, laterality, protocol, or contrast details. Missing UNDERSTAND study context remains unresolved, and no nearest procedure is chosen. This is intentionally not a general post-coordination or terminology management framework.

## Providers and reference resources

The small `TerminologyProvider` interface returns deterministic local candidates. RadLex 4.3 serves radiology clinical concepts and independent anatomy mappings. LOINC/RSNA Radiology Playbook 2.82 serves whole study/procedure identity only, never clinical findings. Both reuse the existing Reference Model's activated, imported concepts and source provenance under external `D:\MedNexus\Reference_Data`. Curated compatibility terms without an equivalent external mapping cannot produce an authoritative code. There are no runtime network requests or hand-written disease-code lists. SNOMED CT has an optional provider interface only; no SNOMED content is bundled or required. Licensed source acquisition and activation remain separately governed.

Study identity carries the accepted examination name, modality, body region, and laterality from UNDERSTAND, plus an independent exact Playbook mapping when one exists. A closest procedure is never selected for coverage. Anatomy is mapped separately from the clinical concept; laterality and lesion extent remain compositional attributes, not forced into an over-specific post-coordinated code.

## Measurements and provenance

V0 recognizes numeric `mm` and `cm` length values only. It retains the exact original measurement text/value/unit and a deterministic source observation path. `cm` converts to `mm` using decimal arithmetic (for example, `1.4 cm` to `14 mm`); `4 mm` remains `4 mm`. Unknown units remain `UNMAPPED`; malformed or unitless measurements require review. No incompatible dimension is converted or guessed. Source-specific observations and multiple measurements remain separate. The result records UCUM source-unit code and conversion method, without claiming to implement the full UCUM catalogue.

The trace is `StandardizedClinicalFact.source_fact_id` → original EXTRACT canonical fact → its protected evidence anchors → protected report. Provider systems and versions, source report ID, mapping method/status, and review decisions are retained. Technical diagnostics contain fact counts, mapping coverage, provider versions, unavailable providers, and bounded failure codes such as `PROVIDER_UNAVAILABLE`, `REFERENCE_DATA_MISSING`, `AMBIGUOUS_MAPPING`, `UNMAPPED_CONCEPT`, `INVALID_MEASUREMENT`, and `STANDARDIZATION_RUNTIME_FAILURE`. Raw source text is not logged.

## Journey and review

`POST /api/v1/understanding/journey-runs/{run_id}/documents/{document_id}/standardize` is Stage 04. EXTRACT `COMPLETE` or `NEEDS_REVIEW` permits processing; EXTRACT `FAILED`, `BLOCKED`, or absent result blocks it. A new EXTRACT run invalidates the previous STANDARDIZE result. The stage can be `COMPLETE` with legitimate unmapped concepts, `NEEDS_REVIEW` for ambiguous mapping or invalid measurement, and `FAILED` only for technical/contract failure. EXTRACT's review state remains independent. The compact workspace shows matched/review/unmapped counts, measurements, study identity, and per-fact mapping details; it does not present technical diagnostics prominently or redesign EXTRACT.

## Acceptance and limits

Acceptance requires unchanged source facts and clinical meaning, deterministic source fact IDs and mappings, no invented codes, conservative ambiguity handling, reversible measurement conversions, complete provenance, Journey gating, and no R2.0C regression. Focused tests use offline synthetic providers; active local reference providers are read without committing licensed distributions. External source availability and terminology coverage can change and must be reviewed/versioned. Clinical records still need human review before becoming accepted analytics inputs. The next horizontal dependency is an accepted, reviewed standardized record for future ANALYZE; ANALYZE is not implemented here.

Before the component-aware correction, the production-equivalent in-process Journey was exercised on the three accepted synthetic references, without printing report text. US_CT_07 retained 16/16 facts (1 RadLex concept matched, 15 unmapped, one length measurement normalized); US_X-ray_04 retained 9/9 (0 matched, 9 unmapped); IN_MRI_02 retained 12/12 (0 matched, 12 unmapped, two measurements normalized). These are historical whole-label-only baseline counts. Each original EXTRACT result remained structurally identical after STANDARDIZE. All three whole-study Playbook lookups were `UNMAPPED`; no closest procedure was substituted. Mapping coverage is intentionally not an acceptance percentage.

The accepted UNDERSTAND study context was CT / HEAD for US_CT_07, unresolved modality and region for US_X-ray_04, and MRI / EXTREMITY with no structured laterality for IN_MRI_02. STANDARDIZE carried those values as given. In particular, it did not promote MRI shoulder/left from raw narrative text when the accepted structured context did not provide those attributes. Study-identity specificity therefore remains partial pending a separate governed UNDERSTAND-context improvement, not an R2.0C EXTRACT change.

The component-aware correction was then checked in six sequential production-equivalent synthetic Journeys, with the same provider code held fixed across all six. The EXTRACT result, including all canonical facts and their assertions, hypothesis statuses, salience, and evidence anchors, was structurally identical before and after STANDARDIZE in every run. Counts below separate exact full display matches from exact component matches; the latter do not assert complete-fact equivalence.

In particular, no Hill-Sachs deformity or Bankart deformity code is substituted for a lesion phrase. Further specificity requires separately accepted structured EXTRACT or UNDERSTAND fields and is outside this provider correction.

## Human acceptance and Stage 04 workspace

Human browser review accepted the functional Stage 04 Journey wiring. IN_MRI_02 reached STANDARDIZE from EXTRACT with all 12 canonical facts preserved, 9 component mappings visible, understandable `NEEDS_REVIEW` and `UNMAPPED` states, and a separate Study Identity presentation. The component presentation does not imply whole-fact equivalence. The MRI-to-MR spelling normalization does not infer anatomy or laterality. Original measurements remain visible beside `1.4 cm → 14 mm` and `4 mm → 4 mm`, and navigation back to EXTRACT works. US_X-ray_04 showed “No diverticulum” with `Assertion = ABSENT`; mapping its underlying concept did not present a positive diagnosis. The human decision accepted component-aware standardization and the Stage 04 workspace, and deferred the final Unified Journey visual redesign.

## Accepted limitations and next milestone

Coverage is deliberately conservative. Qualified and composite facts commonly remain `NEEDS_REVIEW` or `UNMAPPED`; these are valid governed outcomes, not technical failures. Study Identity cannot be more specific when accepted UNDERSTAND context lacks anatomy, laterality, or protocol. LOINC/RSNA procedure mapping must not choose a closest procedure. A RadLex component code is not a whole-fact code. UCUM V0 covers the currently required length-unit scope, notably `mm` and `cm`, rather than the full catalogue. Licensed SNOMED content remains optional and is not bundled. The current UI is a functional Stage 04 workspace, with the final Unified Journey experience deferred. None of these limitations reopens UNDERSTAND, EXTRACT, or R2.0C synthesis during closure.

The authority boundary remains UNDERSTAND → recognized document and study context; PROTECT → safe patient analytic context; EXTRACT → clinical meaning and immutable `CanonicalClinicalFact`; STANDARDIZE → additive terminology, independent anatomy and study identity representation, measurement/unit normalization, review status, and mapping provenance. STANDARDIZE does not discover findings, change assertion/hypothesis/salience, merge or split facts, infer unsupported anatomy, or invent codes. The accepted flow is canonical fact → whole-label lookup → structured components and anatomy → assertion and qualifiers preserved separately → UCUM measurement and study identity normalization → mapping review and versioned provenance → `StandardizedClinicalFact`.

**Next milestone: R4.0A — ANALYZE V0.** It will consume governed report records produced by the preceding Journey, without rediscovering or reinterpreting facts. Initial direction: collection-level frequencies, distributions, stratification, and co-occurrence, with correct denominators and explicit eligibility/exclusions; no causal inference or population-prevalence claims without a population denominator. Work remains horizontal first, polish later, toward one platform, one Journey, and multiple domain intelligence packs. Radiology and Public Health will ultimately share the Journey shell, lifecycle, human review workflow, batch/collection mechanics, analytics eligibility, provenance/governance, and visual identity. Neither ANALYZE nor that platform redesign is implemented here.
