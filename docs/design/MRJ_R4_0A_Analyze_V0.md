# R4.0A — Radiology ANALYZE V0

**Status: ACCEPTED / CLOSED FOR HORIZONTAL PROGRESSION.** Functional Stage 05 browser review and the controlled co-occurrence presentation gate are accepted. Final ANALYZE visual/UX design and Unified Journey UX are deferred; this is not final UX acceptance. R3.0A STANDARDIZE V0 remains closed. Stage 05 is a descriptive, report-level transition from governed report intelligence to collection intelligence. It does not implement VISUALIZE, INDICATORS, a final Unified Journey design, predictive modeling, or patient-level analysis.

## Authority and report-to-collection handoff

UNDERSTAND owns recognized document and study context, PROTECT owns safe patient analytic context, EXTRACT owns immutable clinical facts, and STANDARDIZE owns additive terminology/unit/study identity. ANALYZE reads a bounded structured projection of those results. It never parses original or protected report text, raw RadGraph entities, extraction candidates, repeated mentions, or evidence quotes. A `JourneyRun` is the current bounded process-local processing event; a Batch journey means files were processed together. A `ReportCollection` is an analytical cohort that can span one or more Single or Batch journeys. These are different identities and lifecycles.

Creating or extending a collection freezes atomic report projections while the Journey is available. A source-content SHA-256 is used as an opaque stable report identity when available; otherwise the identity is scoped to the Journey/document. Duplicate membership is rejected. Each projection retains only structured study/patient-safe dimensions, stage/review states, canonical fact identities and assertion/hypothesis roles, independent anatomy/laterality, conservative standardized mapping metadata, and source-linked standardized measurements. It omits source/protected narrative, evidence anchors and quotes, candidate counts, raw engine output, PDF bytes, and direct patient identifiers. Collection data is local clinical data and must be protected by the host's filesystem controls.

The V0 store writes immutable collection versions and AnalysisRun results as JSON outside Git. On Windows the default is `D:\MedNexus\Analysis_Workspace`; `MRJ_ANALYSIS_STORE_DIR` may select another governed local location. Each membership change increments `version`, retaining the old version snapshot. An AnalysisRun binds collection ID, version, contract, filters, and review-inclusion choice. The same inputs yield the same analysis ID and stored result; rerunning an old version never silently adopts later members. Writes are atomic file replacements. This is a small local validation store, not a multi-user database or final record-governance system. Source Journeys may expire while saved collection versions remain analyzable.

## Eligibility and explicit V0 review policy

Each member is `ELIGIBLE`, `NEEDS_REVIEW`, or `EXCLUDED` with reasons. Failed/blocked EXTRACT or STANDARDIZE, missing canonical facts, synthesis coverage failure, and invalid Radiology context are excluded. Valid structured records with unresolved PROTECT, EXTRACT, STANDARDIZE, or fact review are `NEEDS_REVIEW`. `ELIGIBLE` requires current stage contracts to be complete without these review flags; it does **not** assert a human review workflow that does not exist. The conservative default includes only eligible records. An operator may explicitly check **Include review-required records for validation only**; the AnalysisRun records this policy and reports how many included members still need review. Excluded reports never enter the denominator. A structured filter is recorded in policy and removes reports from both numerator and denominator, with filtered-out IDs retained. No eligible denominator produces no frequency percentage and the `NO_ELIGIBLE_REPORTS` or `ALL_REPORTS_REQUIRE_REVIEW` diagnostic.

`REPORT_LEVEL` is the only implemented analytical level. Each eligible report contributes at most once to a given finding/negative/hypothesis identity, regardless of mentions, evidence anchors, or duplicate canonical rows. Mention count, fact count, measurement sample count, and report count remain distinct. Patient-level analysis is **NOT AVAILABLE** until PROTECT supplies a validated stable pseudonymous subject key; demographics, names, dates, or heuristic matching never substitute for it.

## Analytical identity and outputs

An unambiguous authoritative whole-label (or exact canonical concept with assertion separate) standardized code may identify the clinical concept. Otherwise an MRJ canonical-concept identity is used; absent even that, the identity is report-specific to avoid unsafe cross-report collapse. Component-only RadLex codes never replace the whole clinical fact. Anatomy and laterality remain independent identity dimensions so site-specific facts do not silently merge. Unmapped and review-required facts survive analysis via the canonical fallback. Mapping status and component availability are summarized separately; component counts are never called whole-fact matches.

The `CollectionAnalysis` result records collection ID/version, AnalysisRun ID, generated time, domain, analysis level, eligibility policy and lineages, collection summary, finding frequencies, diagnostic consideration frequencies, pertinent negative frequencies, uncertain facts, measurement distributions and coverage, stratifications, co-occurrences, field coverage, standardization coverage, diagnostics, and provenance. Every count/frequency row states metric type, report-level analysis, numerator, denominator, value (or null if denominator zero), eligibility rule, exclusions, collection/version/run IDs, and contributing report IDs. Internal report IDs are lineage, not patient identities.

PRESENT findings, documented ABSENT facts, UNCERTAIN facts, and diagnostic hypotheses occupy distinct result lists. Hypotheses retain `FAVORED`, `POSSIBLE`, `LESS_FAVORED`, or `LESS_LIKELY` and never count as confirmed finding frequency. Negative facts describe documented absence, not disease occurrence. Report-level co-occurrence pairs only PRESENT findings in the same report; it is not a source-supported clinical relationship, association, correlation, cause, or risk factor. The complete `cooccurrences` result retains all valid pairs, including one-off pairs, with numerator, included-report denominator, and frequency. The separate V0 default presentation selects pairs present in at least **2 included reports**, orders them by reports-with-both descending, report-level frequency descending, then concept identities, and shows the **top 20**. The threshold is visible in Stage 05. When no pair repeats, the view says “No repeated co-occurrence patterns were observed in this collection”; it does not imply that the complete AnalysisRun has no one-off co-occurrences. The collapsed technical details disclose complete and one-off pair counts; the full AnalysisRun remains available for inspection and later visualization. No association statistics are calculated.

Measurement distributions consume STANDARDIZE's normalized values only. Aggregation requires the same analytical fact identity, explicit structured measurement type, dimension, and normalized unit. The result keeps source measurement IDs and original strings. Different diameter/depth/velocity/time/volume types are never pooled. R3.0A V0 does not yet produce reliable measurement type/dimension, so current real reports have **no comparable measurement distributions**; they are counted as unclassified measurement coverage rather than given a misleading mean. Typed synthetic fixtures verify min/max/mean/median and `1.4 cm` / `14 mm` comparability. ANALYZE never guesses a unit or reconverts raw text.

Structured strata include modality, body region, laterality, report year, sex, age band, facility, region, Batch ID, and standardization status when available. `MISSING` is an explicit bucket and included in the denominator. Only PROTECT's `KNOWN` safe context can supply sex, age, geography/facility, or clinical report/service time; upload or processing timestamps never substitute for clinical dates. If safe numeric age exists, general V0 bands are `0–17`, `18–39`, `40–64`, and `65+`; invalid/missing ages stay missing. Coverage reports available and missing counts for these dimensions plus clinical facts, measurements, and standardized concept mapping. Standardization coverage is fact-level: whole-fact matched, review, unmapped, and separately component mappings available. No mapping percentage is a clinical extraction quality score.

## Stage 05 interface and scientific limits

After a valid STANDARDIZE result the existing Journey exposes **Continue to ANALYZE**. The functional Stage 05 workspace can select a saved collection, create one from the current Journey, or add current Journey reports to a collection, then run conservative or explicit validation analysis. It shows collection membership/eligibility counts, summary, eligibility policy, findings, diagnostic considerations, negatives, measurements, strata, co-occurrence, coverage, and standardization coverage. Technical/provenance is collapsed. The active rail shows Stage 05 and return to STANDARDIZE is available. The UI is lists and compact metrics, not a dashboard or chart system. Selected filters are supported by the analysis API for structured fields; a complex cohort/filter builder is deferred.

All displayed frequencies are **report frequency within included collection reports**, never population prevalence or incidence. No population denominator, causal inference, risk estimate, association test, or governed indicator is produced. `NO_ELIGIBLE_REPORTS`, `ALL_REPORTS_REQUIRE_REVIEW`, `INSUFFICIENT_COMPARABLE_MEASUREMENTS`, `MISSING_ANALYTIC_DIMENSION`, and `INVALID_COLLECTION_VERSION` are explicit diagnostics; unexpected runtime failures remain HTTP failures rather than fabricated metrics.

## First functional validation collection and limits

The first collection uses ten diverse **synthetic** reports from the existing R1 Radiology validation corpus, spanning CT, MRI, X-ray, ultrasound, Doppler, mammography, and fluoroscopy. It is a functional/demo cohort, deliberately not population-representative. The pipeline is UNDERSTAND → PROTECT → EXTRACT → STANDARDIZE before collection snapshot; reports legitimately blocked by an upstream stage remain members but are excluded from analysis. The saved collection is `R4.0A Synthetic Radiology Validation Collection`, ID `91ac2ce09e884719a3aa5b7f288e40d1`, version 1. Its ten members are 0 eligible, 8 review-required, and 2 excluded (blocked EXTRACT). Conservative analysis has no included denominator and emits no finding frequencies. Explicit **validation-only** inclusion yields 8 included reports, 55 canonical facts (31 PRESENT, 19 ABSENT, 1 uncertain, plus 4 diagnostic hypotheses), 3 authoritative whole-fact mappings, 25 review mappings, and 27 unmapped concepts. The result contains 31 finding-frequency rows, 4 diagnostic-consideration rows, 19 documented-negative rows, and the complete set of valid co-occurrence pairs; only repeated pairs enter the bounded default display. For example, cerebral atrophy occurs in 1/8 included reports, metastatic tumor `FAVORED` is a diagnostic consideration in 1/8, and a documented absence is kept separate. No comparable measurement distribution is asserted because current source records lack governed measurement type/dimension. Modality is available in 6/8 included reports, body region in 5/8, and clinical facts in 8/8. No source report text, evidence spans, or identified content is written into the collection store.

Under analysis contract `mrj-radiology-analysis-v0.4`, the explicit validation result contains **94 valid one-off pairs and zero repeated pairs**. All 94 remain in the structured AnalysisRun; Stage 05 shows the no-repeated-pattern state. The conservative result includes zero reports and zero pairs. Selected synthetic source filenames: `US_CT_07`, `IN_CT_02`, `IN_MRI_02`, `IN_MRI_07`, `US_X-ray_04`, `IN_X-ray_06`, `US_USG_03`, `IN_Doppler_05`, `IN_Mammogram_04`, and `IN_Fluoroscopy_07` (each with `_IDENTIFIED_SYNTHETIC.pdf` suffix). The two blocked EXTRACT members (`IN_CT_02` and `IN_MRI_07`) remain in collection membership and explicit exclusion counts; no blocked member affects an analytical denominator.

R4.0A does not add a human review workflow, persistent governed report registry, broad terminology tuning, a patient denominator, clinical measurement-type extraction, temporal inference, inference statistics, Public Health pack, Stage 06 visualizations, or Stage 07 indicators. These are separate future decisions. The next horizontal dependency is Stage 06 VISUALIZE consuming this governed `CollectionAnalysis` result without recomputing clinical facts or changing the analysis denominator.

## Closure decision and deferred presentation work

**R4.0A ANALYZE V0: ACCEPTED / CLOSED FOR HORIZONTAL PROGRESSION.** The collection model, eligibility and denominator discipline, descriptive analytics, and co-occurrence V0 with its repeated-pattern default presentation threshold are accepted. Final ANALYZE visual/UX design and Unified Journey UX are **DEFERRED**, not accepted by this functional closure. Known later design work includes Stage 05 density, inconsistent Journey presentation, visible internal/source/hash IDs, typography and spacing, navigation, stage-to-stage identity, collection creation, and overall workflow clarity. These do not block the horizontal sequence. **Next milestone: R5.0A — VISUALIZE V0.**
